## 2. 디자인(UI): 읽히는 카드로

### 문제와 해결

| 문제 | 원인 | 해결 | 결과 |
|---|---|---|---|
| 초기 카드의 글자가 얇고 흐림 | 가변 폰트가 기본값(Thin)으로 그려짐 | 실제 굵기를 지정해서 렌더 | 비교 이미지 첫 열과 둘째 열 대비 |
| 표지가 피드에서 눈에 안 띔 | 작은 제목, 장식 요소 | 썸네일형 표지: 큰 굵은 제목, 윤곽선, 수치 강조, 배경 사진 색에서 뽑은 강조색 | 둘째 열 → 셋째·넷째 열 |
| 표지 제목이 "80%"처럼 숫자만 | 숫자 추출만 하고 대상은 안 붙임 | "숫자 + 단위 + 대상" 구절 규칙 | `S6` 기준과 테스트 |

| 카드마다 글자 크기·위치가 다름 | 레이아웃별 개별 계산 | 본문 패널 하나로 통일, 위치 상수화(영상 없는 카드는 중앙) | 타이포그래피 불일치 제거 |
| 수치 상자 안 내용이 13.5px 아래로 치우침(사용자가 게시된 카드에서 발견) | 고정 보정값(+42, +30)으로 위치를 잡아 글자 높이가 바뀌면 어긋남 | 실제 글자 높이를 측정해 상자 중앙에 배치 + 픽셀을 재서 검증하는 테스트(±5px) | 13.5px → 1.5px 이내, 비교 상자의 밑줄이 숫자를 파고들던 문제도 해소 ([비교](retrospective/stat_box_centering.png)) |
| 마지막 카드가 150자 문단 | AI가 앞 내용을 다시 요약 | 한 줄 핵심 + 수치 칩 3개 + 저장 안내. 앞 카드에서 검증된 값만 재사용 | 글자 수 약 150 → 약 30자, AI 호출도 감소 |
| 밝은 배경에서 글자가 묻힘 | 밝은 사진을 우선 선택 | 어둡고 주제와 관련 있는 사진 선호 + 평균 밝기 기준 | `S9` 기준 |

- 영상:본문 50:50: 영상이 너무 작아져 56:44로 되돌렸습니다.

## 3. 영상 정책(UX): "많이"가 아니라 "맞는 것만"

초기에는 **모든 카드에 영상을 붙이려** 했습니다. 이 결과를 겪으면서 정책이 바뀌었습니다.

1. **관련 없는 영상이 붙음.** 영상 검색이 주제와 비슷한 키워드로 stock 영상(Pexels)까지 끌어와서, 내용과
   무관한 장면이 카드 흐름을 깨뜨렸습니다.
2. **원인을 나눠서 확인.** (가) 자막이 없는 영상, (나) 화면이 멈춘 제목 카드 영상, (다) 광고·투자 선동 영상,
   (라) 주제어는 맞지만 다른 대상을 다룬 영상이 섞여 있었습니다.
3. **조건을 코드로 고정.** 영상은 아래를 모두 만족할 때만 붙입니다.
   - 자막으로 **슬라이드 내용과 일치**함을 확인(강한 모델이 판정)
   - 실제로 **화면이 움직임**(정지 영상 거부)
   - **광고·투자 선동이 아님**
   - 검증 기록이 남아 있음(`S4`, `S5`)
4. **맞는 영상이 없으면 문장 카드로.** 대체 영상은 쓰지 않습니다. 이번 #28 세트는 후보 7개를 검토해서 0개가
   조건을 통과했고, 모두 문장 카드로 나갔습니다.

교훈: 자동화의 품질은 "붙이는 능력"이 아니라 **"붙이지 않는 기준"**에서 나옵니다.

## 4. 품질과 안정성

### 구조
- **근거 우선:** 카드의 모든 주장은 원문 근거에 연결되고, 숫자·날짜·고유명사는 결정적 코드로 대조합니다.
  통과하지 못하면 재생성하고, 그래도 안 되면 게시하지 않습니다(fail-closed).
- **출력 기준 `docs/OUTPUT_STANDARD.md`:** 승인 화면에 올라오기 전에 모든 세트가 자동 점검을 통과해야
  하고, `block` 항목이 남으면 게시가 거절됩니다.
- **사람 승인:** 승인한 바로 그 세트만 게시됩니다(대기열의 "다음 차례"를 대신 올리는 일을 막음).

### 재시도에서 얻은 배움
재시도 원인을 기록하기 시작하자(10월), **전체 재시도의 큰 몫이 숫자 표기 차이**였습니다.
"1.5 million ... workers"를 "150만 명"으로 읽지 못하는 식입니다. 처음에는 표기가 나올 때마다 하나씩
고쳤는데, 그러면 같은 일이 반복됩니다. 그래서 **표기 코퍼스 테스트**(77개 사례: 통과해야 할 것과 거절해야
할 것)를 만들어 고칠 때마다 전체를 검증하게 했습니다.

### 회귀 측정으로 확인한 것
골든 기사 11개를 실제 파이프라인에 돌렸습니다(10-18).

| 실행 | 성공률 | 비용 | 재시도 |
|---|---|---|---|
| 1차 | 64% | $1.10 | 36회 |
| 2차 | 55% | $0.88 | 30회 |

실패는 대부분 **편집 점수 판정의 변동**과 **비용 상한**이었고, 기사의 수치 수는 성공과 상관이 없었습니다
(후보 점수를 만들어 같은 11개로 검증했을 때 높은 점수 기사도 실패). 그래서 "점수로 후보를 고르는 기능"은
**연결하지 않았습니다.** 측정으로 기각한 결정입니다.

그 뒤 판정 기준이 우리 표지 규칙(22자, 수치+대상)과 모순되어 같은 지적을 반복하던 것을 찾아 고쳤습니다.
고친 뒤 #28 재시도는 한 번에 통과했지만 표본이 1건이라 **개선을 확정하지 않고 계속 측정 중**입니다.

## 5. 운영과 비용

- **비용 계측:** 호출마다 토큰·비용을 단계별로 기록하고, 세트당 상한을 두었습니다($0.35 → $0.20).
  상한에 걸리면 이미 쓴 비용은 돌려받지 못하므로, 같은 기사를 반복 시도하지 않고 일찍 포기하는 규칙을
  넣었습니다.
- **정직한 수집 보고:** "3개 요청, 2개만 적합"일 때 3개라고 표시하던 문구를 고쳐서 실제 개수와 제외 사유를
  그대로 보여줍니다. 모자란 개수를 다른 주제로 채우지 않습니다.
- **신선도:** 발행 2일 이내 기사만 사용하고, 대기 중에 오래된 기사는 사용 시점에 다시 검사합니다.
- **자동화 범위:** 게시는 항상 사람의 승인 뒤에만 합니다. 스케줄러로 자동 게시하지 않습니다.
- **토큰 관리:** 만료가 다가오면 대시보드가 경고하고, 게시 시점에 자동으로 갱신합니다.

## 6. 사고 회고 (비난 없이, 원인 중심)

| 사건 | 원인 | 재발 방지 |
|---|---|---|
| Threads 게시가 **다른 프로젝트의 계정**으로 올라감 | PC의 사용자 환경변수(다른 프로젝트용 토큰)가 `.env`보다 먼저 읽힘. 게시 후 한쪽 계정만 확인해서 "실패"로 오판 | 자격증명을 `.env`에서만 읽도록 고정 + **게시 직전에 토큰의 계정이 맞는지 확인**, 다르면 중단. 이후엔 양쪽 계정을 모두 확인 |
| 파일을 저장하면 생성 중인 작업이 죽음 | 개발 서버의 자동 재시작이 작업 스레드를 종료 | 생성 중에는 파일을 수정하지 않는 규칙 |
| 테스트가 몰래 AI를 호출해서 느리고 비용 발생 | 테스트가 각도 선택기와 영상 검증을 실제로 호출 | 해당 경계를 가짜로 대체(테스트 100초 → 4초) |
| CI만 실패 | 로컬에는 `.env`가 있고 CI에는 없음 | 테스트가 각자 설정을 만들고, 푸시 전에 `.env` 없는 복사본에서 전체 테스트 실행 |
| 비용 상한이 걸려 카드 없이 비용만 소모 | 상한 도달 시 중간 결과를 못 씀 | 반복 실패는 일찍 중단, 상한을 낮춤 |

## 7. 해 보고 버린 것 (실패도 기록)

- **AI 사전 점검**(후보를 미리 LLM으로 걸러내기): 실패할 기사를 구별하지 못해서 제거.
- **후보 점수 선정:** 위 회귀 데이터로 효과가 없음을 확인하고 참고용으로만 남김.
- **네이버 랭킹 뉴스 소스:** 계정 성격과 무관한 국내 이슈가 섞여서 제거.
- **모든 카드에 영상 부착:** 위 3장 참조.
- **자동 댓글로 노출 늘리기:** 공식 API로 불가능하고 약관 위반이라 계획하지 않음(사람이 쓰는 댓글 초안 지원으로 대체).

## 8. 현재 상태와 솔직한 한계

- **품질:** 출력 기준과 검증은 안정되었지만, 생성 성공률은 아직 확정하지 못했습니다(회귀 55~64%에서
  판정 기준을 고친 뒤 소표본 측정 중). 목표는 성공률 80% 이상, 세트당 $0.12 이하입니다.
- **성장:** 품질이 올랐다고 노출이 오른 것은 아닙니다. 10월 말 기준 계정 팔로워는 매우 적고(인스타 2명),
  최근 세트의 도달은 0에 가깝습니다. **지금의 병목은 카드 품질이 아니라 배포(노출)입니다.**
